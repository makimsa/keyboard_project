# Project Proposal — Voice-Command Keyboard

**Name:** Sahil Makim
**Class:** CS 3651 (Prototyping Intelligent Devices)


## Description
I'm building a 40% mechanical keyboard, 12 by 4 matrix with 47 keys. This keyboard should work as a normal wired keyboard, but it adds a new voice-command mode. When a user presses a dedicated button, the keyboard listens to a I2S MEMs microphone to process voice commands. the voice command mode is an on-device keyword spotting model that classifies spoken phrases against a fixed list of commands. The recognized command is then sent to the computer as a keyboard shortcut; mimicing pressing the required keys in the required order for some specified output. As an example:
- "close tab" -> cmd+w
- "open brave" -> cmd + space, delay, 'brave' + enter
- "school mode" -> cmd + space, delay, brave new tab , delay, gatech.instructure.com + enter.
The goal is to setup a voice command method to trigger software defined macros saved and setup in the microcontroller. 

Speech recognition should run on the microcontroller itself, not on the host computer. This makes the device implement more processing than just sending all the information to the computer for processing. 
So far the scope is restricted to just keyword spotting, as full text to speech cannot run on an MCU (maybe a command to start text to speech to run on the computer using the on board mems microphone).

## Block Diagram
![[Drawing 2026-10-25 23.00.46.excalidraw]]

- **Inputs:** key matrix (12×4) and I2S microphone; voice-mode push button.
- **Processing (on MCU):** matrix scan + debounce; on-device keyword spotting;
  command→shortcut lookup.
- **Outputs:** USB HID keystrokes to the computer.

## Goals + Stretch

**Core:**
- Working 40% keyboard: full 12×4 matrix, debounce, function layer, USB HID,
  types normally on macOS.
- Voice mode: 10–15 distinct commands recognized **on-device** and sent as the
  correct shortcuts.
- 3D-printed plate + case housing all electronics.

**Stretch:**
- Larger command vocabulary; a custom wake word instead of a button.
- Layers / macros beyond the basic function layer.
- Custom PCB instead of hand-wiring.
- ability to use the keyboard with ANY device without requiring auxilary programs on computer would be nice, not sure on the feasibility. 

## Mid-project Review Deliverable

Hard deliverable: on a breadboard, the ESP32-S3 recognizes at least 5 spoken commands on-device and prints them, and a small test matrix (a few switches with diodes) sends correct keystrokes to the computer over USB HID.

This proves that the on-device speech recognition and USB HID output work on the real hardware, early enough to re-scope if keyword spotting struggles.

## Potential changes

- **Speech approach fallback:** start with ESP-SR/MultiNet (Option A). If its fixed command set or accuracy is too limiting, fall back to a custom Edge Impulse / TFLite-Micro keyword-spotting model (Option B).
- **MCU:** the project *requires* an ESP32-S3 with PSRAM.
- **Scope reduction if needed:** cut command count, or switch from hold-to-talk to a simpler always-listening-while-pressed model.
- **Noise handling:** if background noise hurts accuracy, reduce the vocabulary to more acoustically distinct phrases and tune mic gain/placement.
